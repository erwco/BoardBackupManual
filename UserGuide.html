1. Overview

This script downloads backup files from Azure cloud storage and copies them to a local network drive (filer). It uses Microsoft's AzCopy tool to transfer files efficiently - only new or changed files are downloaded on each run. The script is idempotent - you can run it multiple times safely without duplicating data or causing any side effects.

The script automatically:

  • Downloads AzCopy if it is not already present (one-time setup)
  • Asks you for a SAS token (a temporary access key) and validates it
  • Determines which backup folders to download based on configured dates
  • Syncs each folder to the network destination
  • Prints a summary of what was transferred
Debug mode To save a detailed log file for troubleshooting, use Run-Backup-Debug.bat instead. See Log Files for details.

2. Prerequisites

Requirement Details
Windows 10 or 11 PowerShell 5.1 is included by default. No extra installation needed.
Internet access Required to reach Azure Storage and to download AzCopy on first run.
Global Protect connection Required to reach the network destination (filer).
SAS token A temporary access token for Azure Storage, e.g. sv=2024-11-04&ss=f&srt=sco&sp=rl&se=2026-05-01T00:00:00Z&sig=...
Network drive access You must have write access to the destination folder configured in backup-config.json.
No admin rights needed You do not need administrator privileges on your computer to run this script.

3. Before You Start

1
Unblock the files after downloading
Files received via email or downloaded from the internet are blocked by Windows for security. You must unblock them before running the script.
  • If you received a .zip file: right-click the zip file → Properties → check Unblock at the bottom → click OK, then extract the contents.
  • If you received individual files: right-click Run-Backup.bat → Properties → check Unblock → OK. Repeat for Backup-BoardApp.ps1 and azCopyInterface.psm1.
Skipping this step? If you do not unblock the files, Windows may silently prevent the script from running or show a security warning.

2
Ensure you are connected to Global Protect
It is best to be on the Nyon campus with Global Protect connected to Campus Primary to reach the network destination.

3
Copy the SAS token to your clipboard
Select the entire SAS token text and press Ctrl+C to copy it. You will paste it into the script when prompted.

4. Running the Backup

1
Double-click Run-Backup.bat
A blue/black command window will open.
2
First run only - AzCopy download
If this is the first time you are running the script, it will automatically download AzCopy from Microsoft. This takes a moment and only happens once. You will see a yellow message: "[Setup] azcopy.exe not found - downloading (this is a one-time setup)..."
3
Enter the SAS token
When prompted, right-click in the command window to paste the SAS token from your clipboard. The token will not be displayed on screen for security reasons - this is normal. Press Enter to confirm.
Pasting into the command window In the PowerShell/Command Prompt window, right-click pastes the clipboard contents. You will not see any characters appear - the input is hidden. Just right-click once and press Enter.
Watch out for hidden characters When copying the SAS token, make sure no extra spaces, line breaks, or hidden characters are included. Copy only the token text itself - do not include surrounding quotes or whitespace.
4
Wait for the backup to complete
The script will validate your token, then begin syncing backup folders. You will see a progress bar for each folder being transferred. Do not close the window while the backup is running.
5
Review the summary
When finished, the script displays a summary showing which folders were backed up and whether each succeeded or failed. It also shows the total elapsed time.
6
Press Enter to close
The window stays open until you press Enter, so you have time to review the results.

5. What Happens During the Backup

Here is what the script does behind the scenes:

a) Configuration loading

The script reads backup-config.json to determine the Azure Storage URL, the local destination path, and which backup paths to process.

b) Connectivity checks

Before starting any transfers, the script verifies that the network destination folder is reachable. If it is not, you will see a clear error message asking you to check your Global Protect connection.

c) Date calculation

The script calculates which backup snapshots to download based on the BackupDays setting. For example, if BackupDays is set to [1, 16], the script finds the most recent occurrence of each day. If today's date has not yet reached a given day, the script uses that day from the previous month. For example, on April 8 with days [1, 16]: day 1 resolves to April 1, but day 16 resolves to March 16 (because April 16 has not happened yet). It then selects the most recent backup taken before each of those dates.

d) Directory discovery

For each configured backup path (e.g., uefa-c1, uefa-s1), the script lists available backup snapshots in Azure Storage and selects the correct ones based on date and type (LD, CLFFP, QA).

e) File sync

Each selected backup folder is synced to the local destination using AzCopy. Only files that are new or have changed since the last run are transferred. You will see a progress bar with a percentage and transfer speed for each folder.

6. Understanding the Results

At the end of the backup, you will see a summary like this:

  ==================== BACKUP SUMMARY ====================

  Name                                       Result      Source     Dest   Copied
  -------------------------------------------------------------------------------
  2026-03-31 23-50-01-948@@UEFA_LD.hbmp      Completed     7018     0        7018
  2026-03-15 23-50-01-789@@UEFA_LD.hbmp      Completed     7031     0        7031
  2026-03-31 23-05-01-965@@UEFA_CLFFP.hbmp   Completed    22653     0       22653
  2026-03-15 23-05-01-800@@UEFA_CLFFP.hbmp   Completed    22447     0       22447
  -------------------------------------------------------------------------------
  4 succeeded, 0 failed out of 4 total.

Total elapsed time: 0h 12m 34s
Log file location If you used Run-Backup-Debug.bat, you will also see a line showing where the log file was saved.
Column Meaning
Result Completed = success. Failed = an error occurred for that folder.
Source Number of files found in Azure Storage for that backup.
Dest Number of files already present at the local destination.
Copied Number of files that were actually transferred (new or changed). If this is 0, everything was already up to date.
Zero files copied is normal If you run the backup twice and nothing has changed on the server, AzCopy will report 0 files copied. This means the destination is already in sync.

7. Configuration Reference

The file backup-config.json controls the backup behavior. It is pre-configured - you should not need to change it unless instructed by your administrator.

Setting Description Example
StorageUrl The Azure Storage endpoint. https://uefastrg01.file.core.windows.net
Destination Local or network path where backups are saved. \\server\share\backups
BackupDays Days of the month used to select backup snapshots. The script picks the most recent backup before each day. [1, 16]
DirectoryRegex Pattern used to identify backup folder names in Azure. Do not modify this unless instructed. (regex pattern)
SyncTimeoutSeconds Maximum time (in seconds) allowed for syncing a single folder. Default: 18000 (5 hours). 18000
BackupPaths List of backup paths to process. Each entry has:
  • name - a label (e.g. uefa-c1)
  • path - the Azure Storage path
  • types - which backup types to download (e.g. LD, CLFFP, QA)
 (see config file)
Do not edit the config file unless asked Incorrect values can prevent the backup from running. If changes are needed, your administrator will provide the updated file or specific instructions.

8. Log Files

Log files are created when you use Run-Backup-Debug.bat instead of Run-Backup.bat. The standard launcher does not create log files.

When running in debug mode, logs are saved in the scripts\logs\ folder:

scripts\logs\
  ├─ Backup-BoardApp_2026-04-07_10-30-00.log ← Transcript log
  ├─ Backup-BoardApp_2026-03-16_14-22-15.log
  └─ AzCopyLogs/ ← Detailed AzCopy transfer logs

If something goes wrong, run the backup again using Run-Backup-Debug.bat. The log file contains a detailed record of everything that happened. You can send this file to your administrator for troubleshooting.

Security note The SAS token is never written to the log files. It is safe to share log files with your administrator.

9. Security

This script has been designed with security as a priority. Below is a summary of the protections built into the backup process.

Credential Protection

The SAS token is the only secret handled by the script. Multiple layers of protection ensure it is never exposed:

Measure Details
No hardcoded credentials The script contains no embedded passwords, tokens, or secrets. The SAS token is provided at runtime through an interactive prompt.
Hidden input The SAS token is entered as a SecureString - characters are never displayed on screen.
Never stored on disk The token is held in memory only for the duration of the backup. No file is created to store it. It is discarded when the script finishes.
Never written to log files Transcript logging is paused before the token prompt and resumed only after the token is stored securely.
Redacted from error messages If an error occurs, any SAS token fragments in error messages or stack traces are automatically replaced with [REDACTED] before being displayed or logged.
Hidden from process listings The token is passed to AzCopy via a child-process environment variable, not as a command-line argument. This means it is not visible in Task Manager or other process monitoring tools.
Safe to share log files Because the SAS token is never written to log files and is redacted from all error output, you can safely send log files to your administrator for troubleshooting without exposing any credentials.

Data Transfer Security

Measure Details
Encrypted connections All communication with Azure Storage uses TLS 1.2 encryption. The script enforces this at startup to prevent older, insecure protocols from being used.
No temporary files during transfer AzCopy writes directly to the destination folder. No intermediate or temporary files are created on your local machine during the transfer. Data flows from Azure Storage straight to the network destination.
Download integrity verification When AzCopy is downloaded for the first time, the script verifies its digital signature and confirms the signer is Microsoft. If either check fails, the file is deleted and the script refuses to continue.

Input and Data Validation

Measure Details
Token validated before use The token format is checked and a live test request is made against Azure Storage before the backup begins. Invalid or expired tokens are rejected with a clear message.
Path traversal protection Backup folder names received from Azure Storage are validated before use. The script checks that each destination path stays within the configured backup folder - a crafted folder name cannot cause files to be written outside the intended location.
Safe XML parsing Directory listings returned by Azure Storage are parsed using a secure XML reader that blocks external entity injection (XXE attacks).

10. Troubleshooting

Error Message What To Do
"Cannot reach the backup destination..." The network drive is not accessible. Connect to Global Protect and verify you can open the destination folder in File Explorer. Then try again.
"The SAS token was rejected by Azure (access denied)" The token is expired or incorrect. Request a new SAS token from your administrator.
"Cannot reach Azure Storage" No internet connection, or the Azure endpoint is unreachable. Check your internet connection and try again.
"The SAS token cannot be empty" You pressed Enter without pasting anything. Right-click in the window to paste, then press Enter. Remember: the characters will not be visible.
"Failed to download AzCopy" Internet connectivity issue during first-time setup. Check your internet connection and run the script again.
"Configuration file not found" The file backup-config.json is missing from the script folder. Make sure all files are present in the same folder (see Section 2).
"The file 'azCopyInterface.psm1' is missing" A required script file is missing. Re-copy the entire backup folder from its original location.
"Failed after 3 attempts" The SAS token could not be validated after 3 tries. Check that you are copying the full token, verify it has not expired, and run the script again.
"AzCopy sync failed with exit code..." A file transfer error occurred. Check the log file in logs/ for details and share it with your administrator.
The window closes immediately This should not happen. Try running the script manually: open PowerShell, navigate to the script folder, and type:
.\Backup-BoardApp.ps1
Still stuck? Send the log file (from logs/) to your administrator. It contains all the technical details needed to diagnose the problem.

11. Frequently Asked Questions

Can I run the backup multiple times?

Yes. AzCopy only transfers files that are new or changed. Running the backup again is safe and will be much faster if most files are already synced.

How long does the backup take?

It depends on the number and size of files and your network speed. The first run may take longer since all files need to be downloaded. Subsequent runs are faster because only changes are transferred.

Can I move the script folder to a different location?

Yes. You can copy or move the entire folder anywhere on your computer (including a USB drive). Just make sure all files stay together in the same folder.

Do I need to provide the SAS token every time?

Yes. The script never stores the SAS token - for security reasons, it is kept only in memory during the backup and discarded when the script finishes.

What does "0 files copied" mean?

It means the destination already has all the files from Azure Storage. Nothing needed to be transferred. This is normal for subsequent runs.

Can I cancel the backup while it's running?

Yes. Press Ctrl+C in the command window, or simply close the window. No data will be corrupted - AzCopy handles interruptions gracefully. The next time you run the backup, it will pick up where it left off.

Do I need to clean up old log files?

Log files are small and do not accumulate quickly. You can delete old ones from the logs/ folder if you wish, but it is not required.
